## 什么时候用

用户让你评审改动、问「这么改有没有问题」、或者交付前想自查一遍时。

## 步骤

1. 先跑脚本拿改动清单，不要自己拼 git 命令：

   ```
   python skills/review-diff/scripts/collect_diff.py
   ```

   它会输出：改了哪些文件、增删行数、以及每条改动的上下文（已裁到 40 行以内）。
2. 按固定清单逐条检查（五条，别加戏）：
   - 有没有改到不该改的文件（配置、锁文件、别人的模块）
   - 有没有新增依赖（`requirements.txt` / `pyproject.toml` 是否被动过）
   - 有没有 `except: pass` 或吞掉异常
   - 新逻辑有没有被测试覆盖（改了源码但没动测试 = 可疑）
   - 有没有调试残留：`print(`、`TODO`、`breakpoint()`
3. 每条问题写成一行：`文件:行 → 问题 → 建议`。
4. 最多报 5 条，按严重程度排序；没有问题就明确说「没发现问题」，不要凑数。

## 不要做什么

- 不要贴整段 diff 或整段文件，只引用关键那一行。
- 不要顺手改代码 —— 这个技能只读。
- 不要评价代码风格偏好（命名、空行），只报会出事的地方。

## 怎么算做完了

- 跑过 `collect_diff.py`（有真实输出），并且
- 有明确的结论：几条问题 + 每条的文件行号与建议，或「没发现问题」。
