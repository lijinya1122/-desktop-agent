## 什么时候用

用户要你跑测试、问测试为什么失败、或者改完代码需要验证时。

## 步骤

1. 先跑最简命令：`python -m pytest -q`；项目里有自写的测试脚本就用它（如 `python test_stats.py`）。
   **不要一上来就 `-v`** —— 输出太长会挤占上下文。
2. 红了只读失败用例的 traceback，**最多看 3 个**，不要把所有失败都读一遍。
3. 把结论整理成三行（每个失败用例一行）：
   - 哪个用例
   - 期望什么
   - 实际什么（+ 最可能的原因，一句话）
4. 报告完就停。**这一步只报告，不顺手改代码** —— 改不改由用户下一步决定。

## 不要做什么

- 不要为了让测试变绿而删测试、改断言、加 `skip`。
- 不要贴整段 traceback 进回答，只留关键三行。
- 不要反复重跑同一个命令（结果不会变）。

## 怎么算做完了

- 有一条真实的命令输出（退出码或 `N passed / N failed`），并且
- 每个失败用例都有「期望 / 实际 / 原因」三行总结。
