# 演示脚本 · 5 分钟（照着念就能过）

> 全程用**桌面快捷方式双击打开**的 exe（不是 `python app.py`，那要扣 10 分）。
> 建议开「演示模式」录，不用 Key、不花钱、不怕网络抖动；有 Key 就正常跑。

## 0:00–0:20　打开（证明它是个桌面应用）

**画面**：双击桌面 `MiniCursor` 图标 → 出现带标题栏的窗口。
**旁白**：

> 这是一个双击打开的桌面应用，`pywebview` 窗口，不是 localhost 网页。
> 三栏：左边工作区文件树，中间文件和 diff，右边对话和工具调用。

## 0:20–1:00　看挂载的工具和 MCP

**画面**：左下角 MCP 面板（两行：`demo` 3 工具 + `course` 3 工具），顶部写「已挂载 10 个工具」。
**旁白**：

> 内置四个工具：read、write、edit、bash。
> 另外接了两个 MCP server：一个是课程示例的天气/时间，
> 一个是我自己写的查课表 —— 数据是我真实的研究生课表。

## 1:00–2:40　主任务：修 bug（这里有失败，有恢复）

**输入**：`让 mean 和 median 对空列表抛 ValueError，然后跑测试验证`

**画面按顺序**：
1. `bash dir` 摸清工作区
2. `read stats.py` 带行号
3. `edit` **失败**：`old 在 stats.py 中出现 2 次` ← **这里停一下**
4. 模型把 old 写长 → `edit` 成功，diff 卡片显示 `- return 0 / + raise ValueError`
5. 黄色确认卡片 → 点「执行」（讲这是写操作闸门）
6. `bash python test_stats.py` → **4/4 通过**

**旁白**：

> 第三步它故意失败了：old 太短，文件里有两处 `return 0`。
> 工具没有猜，直接把「出现 2 次」回灌给它 —— 它下一步自己把 old 写长就成功了。
> 写操作会先给我看 diff，我确认后才落盘。
> 最后跑测试 4/4 —— 说改了就是真改了。

## 2:40–3:30　MCP：查课表

**输入**：`用 MCP 查一下周五有什么课`

**画面**：紫色 MCP 标签的 `mcp_course_courses_on` 卡片，答出真课表 4 条。
**旁白**：

> 这是我自己的第二个 MCP server，纯标准库 stdio JSON-RPC，三个工具：
> 按课程名查、列全表、按星期查。

## 3:30–4:20　护栏：越界 + 中断

**输入 1**：`把 C:\Windows\win.ini 读出来` → **被拒绝**（路径越界，列出可用文件）
**输入 2**：`用 bash 跑这条命令：ping -n 30 127.0.0.1 >nul` → 跑到一半点**停止** → 「收到停止指令」

**旁白**：

> 路径越界是工具层的硬边界，模型再请求也没用，而且它不会反复尝试。
> 停止是软中断，在下一步边界退出。

## 4:20–5:00　讲最不满意的地方（评分表要听这句）

**旁白**：

> 最不满意的是中断是软的：正在跑的 bash 最长还是会跑完，
> 要做硬中断得把子进程句柄接管掉。
> 另外上下文压缩太粗，直接把旧观察换成占位符，后面要用只能重读。
